# 日语多角色听力音频合成

生成接近真人、角色清楚、与题目逐一对应的日语听力练习音频。优先保证内容准确、角色一致和可验证性，不以夸张变声代替自然表达。

## 必须遵守的要求

- 保留输入原文字词，不擅自纠错、删减、翻译或改写。SSML、停顿和分段只能改变朗读方式，不能改变题库文本。
- 同一段音频内，不同角色必须可辨；同一角色在整段中保持同一声音和基本声线。
- 根据场景选择表达方式：广播正式清晰，客服柔和礼貌，会议沉稳，家庭和同事对话自然口语化，紧急提醒更紧凑，道歉和感谢符合语义。
- 基础参数为语速 `-5%`、音高 `+0Hz`。为区分角色或表达情景，可以做克制的小幅变化；避免导致失真、卡通感或偏离 JLPT 正常语速。
- 可以根据标点、句意和说话人切换补充停顿与断句。优先使用合成标记或音频静音，不把新增标点写回原文。
- 输出完整 MP3。推荐24 kHz、单声道、96 kbps；若现有项目已有统一格式，保持项目格式。
- 官方或已获许可的原版录音默认保持不变，只重新合成原创材料，除非用户明确要求替换。

## 服务与授权

- 优先使用微软日语神经语音。女声优先 `ja-JP-NanamiNeural`；免费 Microsoft Edge 服务可用时，男声优先 `ja-JP-KeitaNeural`。
- 先查询服务当前实际提供的声音，不根据旧列表假设声音一定可用。
- 免费 Edge TTS 适合男女角色区分、语速、音高和停顿控制，但不要声称它支持 Azure 的显式情绪风格。
- 只有在用户具备 Azure Speech 凭据时，才使用 Azure SSML 的声音风格功能。不得要求用户把密钥发到聊天中；密钥应放在被版本控制忽略的本地环境文件或安全凭据存储中。
- 在把题目文本发送到任何在线语音服务之前，确认当前任务已授权外部发送。不要把历史授权或本 Skill 视为永久授权。
- 如果用户未授权在线发送，停在本地方案评估或使用用户明确允许的离线语音方案。

## 角色设计

合成前先建立显式角色表，而不是按对话行临时随机选声：

1. 盘点每段材料的场景、说话人、性别或身份、年龄感和交流关系。
2. 为每个角色指定声音、基础语速、基础音高和切换停顿。
3. 男女性别明确时使用对应声音；性别不明确时依据角色关系选择，但要记录并保持稳定。
4. 当服务只有一男一女两种日语声音时，用小幅语速、音高和停顿差异区分同性别角色，不做明显机械变调。
5. 播音员、主持人、领导、客服、学生和儿童等角色应有一致而克制的声线特征。
6. 对道歉、感谢、犹豫、强调、疑问、紧急通知等句子，基于语义微调韵律；不得改变词句来制造情绪。

## 生成流程

1. 核对音频案例数、问题数和映射关系。一段音频可以对应多道题，不能据此误判为缺失或重复。
2. 为每段原创材料生成角色表，并检查每个说话人都有配置；缺失配置时停止该段生成，禁止静默回退到随机声音。
3. 在临时目录逐句合成，再按角色切换加入自然停顿并合并完整音频。
4. 新文件通过验证后再原子式替换旧文件，避免失败时留下半成品。
5. 不在日志、提交或错误信息中输出密钥、令牌或敏感环境变量。

## 强制质量检查

每次批量生成后至少验证：

- 预期音频数量全部存在，文件名或 audio key 与题库一一匹配。
- 每个文件大小非零且超过合理下限。
- 使用 `ffprobe` 检查编码、声道、采样率、时长和码率。
- 使用 `ffmpeg -xerror` 完整解码每个文件，排除截断、损坏和无效帧。
- 时长与文本量大致合理；异常短音频必须重新生成或人工检查。
- 随机抽查包含男女切换、广播、客服、家庭和多人会议的代表样本。
- 运行项目已有的内容测试、类型检查和音频映射测试。
- 对移动应用执行目标平台导出或构建，确认所有音频进入资源清单；不能只验证源目录中存在文件。
